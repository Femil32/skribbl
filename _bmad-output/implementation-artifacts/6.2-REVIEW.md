## Strengths

- **Sanitized error UI:** `RouteErrorFallback` uses fixed copy; segment `error.tsx` files never log or render `error.message` or `digest` in the tree returned to users.
- **Recovery actions:** `unstable_retry` and guarded full reload are both exposed; DaisyUI structure is consistent with banner patterns.
- **Blocked transport:** `lobbyConnectionBannerModel` sets `showReload: true` and `showRetry: false` for `blocked`; banner renders reload only when parents pass `onReload`, and `LobbyHostPage` / `JoinRoomClient` supply `reloadFullPage` for `blocked`.
- **Exhaustive transport union:** `lobbyConnectionBannerModel` ends with `never` exhaustiveness check — good maintenance guard.
- **Tests:** Model and banner behavior for `blocked` / `fatal` / reload are covered; `RouteErrorFallback` asserts no digest leakage and retry callback.

## Findings

### IN-01 — Dev logging gate vs project-context

**Area:** `apps/web/src/app/error.tsx`, `apps/web/src/app/game/error.tsx`

**Observation:** `console.error(error)` runs only when `NODE_ENV === "development"`. Story / project-context also mentions optional `?debug=1` or localStorage-style gates for noisy diagnostics in non-dev builds.

**Suggestion:** If the project already has a shared debug flag helper elsewhere, reuse it here for parity; if not, this is optional follow-up, not a blocker.

---

### IN-02 — `RouteErrorFallback` reload path untested

**Area:** `apps/web/src/components/RouteErrorFallback.test.tsx`

**Observation:** Tests cover default copy, absence of digest text, and **Try again**. **Reload page** is not exercised (e.g. spy on `location.reload` or verify handler presence).

**Suggestion:** One small RTL test reduces regression risk if the reload button is ever gated or renamed.

---

## Cross-checks (not issues)

- **`fatal` + banner retry while `joined` / `lobby`:** Hooks move terminal failures to `status: "error"` or use `disconnected` after an in-session socket close; main surfaces that show `fatal` wire `onRetry` where the story required. `JoinRoomClient`’s `joined` branch only passes `onRetry` for `disconnected`, which is consistent with current hook transitions (post-join drops are `disconnected`, not `fatal`).
- **DRY:** Root and `game/error.tsx` are identical; acceptable for Next segment boundaries if you want localized `error.tsx` files without indirection.

## Verdict

**Ship:** No critical or warning issues identified at standard depth. Address IN-* items as follow-up if you want strict alignment with extended logging/test conventions.
