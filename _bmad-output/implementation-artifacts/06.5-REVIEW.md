# Code review: Story 6.5 (reduced motion, testids, responsive QA)

**Depth:** standard  
**Files:** `apps/web/vitest.setup.ts`, `apps/web/src/app/join/page.tsx`, `apps/web/src/features/game/canvas/DrawingCanvas.tsx`, `apps/web/src/features/game/canvas/DrawingCanvas.test.tsx`, `apps/web/src/features/game/components/GamePage.tsx`, `apps/web/src/features/game/components/GamePage.test.tsx`, `apps/web/src/features/lobby/components/LobbyHostPage.tsx`, `apps/web/src/features/match/components/PhaseBar.tsx`, `apps/web/src/features/match/components/PhaseBar.test.tsx`, `apps/web/src/features/match/components/PhaseCountdownChip.test.tsx`, `apps/web/src/features/match/components/WordChoicePanel.tsx`

## Summary

Implementation matches the story’s intent: canonical `phase-bar` and `drawing-canvas` hooks, DaisyUI spinners guarded with `motion-reduce:!animate-none`, `PhaseCountdownChip` pulse gated by `matchMedia`, and Vitest coverage for countdown + `PhaseBar`. No security or data-integrity issues surfaced. Residual risk is mostly around **automation invariants** when `PhaseBar` returns `null` and around **global test doubles** skewing motion-related behavior.

---

### WR-01 — `PhaseBar` can return `null` during match-adjacent UI states

**Where:** `apps/web/src/features/match/components/PhaseBar.tsx` (branch `if (!hasMainRow && !hasScoreStrip) return null`).

**Issue:** Acceptance criteria called for `data-testid="phase-bar"` on every non-`null` render of the production component. In practice, `hasMainRow` and `hasScoreStrip` can both be false (e.g. transient roster/local id gaps, or unusual phase/prop combinations), so **no `phase-bar` exists** even though the parent may still be in a “match” shell.

**Fix / mitigation:** Either document that hosts must not mount `PhaseBar` until invariants hold, or render a minimal shell with `data-testid="phase-bar"` (even “skeleton” copy) whenever the parent considers the match header visible. Add a focused test for the edge props that currently yield `null` if that state is reachable in production.

---

### WR-02 — Global `matchMedia` stub always reports “full motion”

**Where:** `apps/web/vitest.setup.ts` (`matches: false` for all queries).

**Issue:** Component tests that do not override `window.matchMedia` behave as if **`prefers-reduced-motion: reduce` is false**. That can hide regressions for trees that combine multiple motion sources (Tailwind variants + JS `matchMedia`) unless each area is explicitly tested.

**Fix / mitigation:** Prefer per-suite mocks (as in `PhaseCountdownChip.test.tsx`) or a small helper that toggles reduced-motion fordescribe blocks; optionally add `prefers-reduced-motion` parameterized tests at layout level (`GamePage` + `PhaseBar` when timer visible).

---

### IF-01 — `PhaseBar` tests do not assert `phase-bar-timer` or countdown wiring

**Where:** `apps/web/src/features/match/components/PhaseBar.test.tsx`.

**Observation:** Stable timer hook `phase-bar-timer` is part of UX-DR15’s surface; current tests only assert the root hook. Low priority if `PhaseCountdownChip` tests already cover urgency classes.

**Suggestion:** One assertion that `getByTestId("phase-bar-timer")` exists when `phaseDeadlineMs` is set for `drawing` / `choosingWord`.

---

### IF-02 — `HTMLCanvasElement.getContext` mock is minimal

**Where:** `apps/web/vitest.setup.ts`.

**Observation:** The 2d stub exposes only `setTransform` / `scale` (enough for layout tests). Flood-fill, stroke, or richer drawing tests could fail silently or behave unrealistically until the stub grows.

**Suggestion:** Extend the mock when adding canvas drawing/replay tests, or isolate canvas logic tests with integration-style mocks per file.

---

### IF-03 — `/game` dev shell vs production chat hook parity

**Where:** `apps/web/src/features/game/components/GamePage.tsx`.

**Observation:** Story notes accept a chat placeholder away from `MatchChatPanel`; `chat-composer-input` appears only on the real match path. Fine for scoped AC, but **Playwright selectors must branch** dev vs lobby/join flows.

**Suggestion:** Single doc line in responsive QA or story Dev Notes stating which URLs expose `chat-composer-input`.
