### WR-01 — Test env mutation without restore

**Where:** `apps/server/src/create-game-server.healthz.test.ts`  
**Issue:** The test sets `process.env.WORDS_PATH` but does not restore or delete it afterward. Vitest usually isolates workers, but leaving env mutated is brittle if file order or pooling changes.  
**Fix:** Capture previous value and restore in `finally`, or `delete process.env.WORDS_PATH` after the assertion block.

---

### IN-01 — Healthz row appears after first paint

**Where:** `apps/web/src/components/SiteFooter.tsx` (`requestAnimationFrame` + `setHealthzHref`)  
**Issue:** The probe link is intentionally deferred; reviewers may see a short flash or layout shift when it mounts. Acceptable per hydration constraints; optional improvement is a stable placeholder height or skeleton line.

---

### IN-02 — Malformed `NEXT_PUBLIC_WS_URL`

**Where:** `apps/web/src/lib/game-ws-url-to-healthz.ts` + footer effect  
**Issue:** `new URL(wsUrl)` throws if env contains a bad string; the effect has no try/catch. Unlikely with controlled deploy config; worst case triggers React error overlay in dev.  
**Fix (optional):** Guard with try/catch and omit the row on parse failure.

---

### IN-03 — Story wording vs. helper behavior

**Where:** Story task “preserving host/port/path base” vs. `gameWsUrlToHttpHealthzUrl`  
**Issue:** Implementation maps `wss://host/path/socket` → `https://host/healthz` (WS path stripped). Tests codify this; it aligns with HTTP `/healthz` on the game listener root. Consider aligning story task text with behavior to avoid future regressions.

---

### IN-04 — Acceptance framing for unset repo URL

**Where:** AC #1 vs. conditional rendering  
**Issue:** AC asks reviewers to reach a repo URL via chrome; implementation hides the row when `NEXT_PUBLIC_REPO_URL` is unset (per tasks). Correct for avoiding fake links; production/demo checklist must set the env. Already documented in README and `.env.example`.
